# C2 角色替换与移动渲染优化

## 2026-09-12：原图重建第二版

当前角色版本 `C2-ORIGINAL-20260912-R2`：GLB 13,873,508 字节，67,754 三角面、4 个蒙皮 primitive、19 骨架。游戏加载器给此原生骨架版本设置 70,000 三角面的上限，旧兼容路径仍为 45,000。保留较多面数是因为更激进的减面损坏了头盔、衣服和甲片轮廓。

新增骨架仅复用动作旋转与落脚目标，不再对网格做非等比拉伸。顶点在 GPU 蒙皮；CPU 每帧适配骨骼。内嵌资源使游戏包约 18.8 MB，支持 `file://` 离线启动。该版本已完成六类动作、离线加载与实际第三人称验证，未重新执行完整发布性能门禁，不沿用首轮或历史版本的帧率数字。

复测：运行 `node tools/verify-c2-integration.cjs artifacts/c2-lux3d-20260912-r2` 检查实际模型；启动游戏按 V 查看角色，再对比同目录的动作截图。完整证据见 `motion-browser-audit.json` 与 `offline-game-audit.json`。

当前可见角色优先使用 aholo 生成、Blender 本地修整和绑定的 C2 GLB；正常加载后移除旧程序化可见皮肤，通用动作与触地系统继续使用。游戏版浏览器统计 43,992 三角形、3 个蒙皮网格、19 骨架，两张 2048×2048 内嵌贴图；GLB 约 9.06 MB。为保持双击即可离线运行，将同一 GLB 编码到离线脚本，游戏 bundle 约 12.6 MiB，是明确的下载/内存体积取舍，不代表性能提升。

原始 96,394 三角模型及本地可编辑工程保留。当前具体检查、完整门禁对应的资产版本和最终局部比例复检见 `HTML5_VERIFICATION.md`。以下 2026-09-08 纹理预算、性能采样和近似建模描述仅为历史数据，不能作为新 GLB 的性能测量结果。

## 参考与交付

按已选 C2 六面图的领肩胸甲、象牙色矿壳、灰褐织物、黑面罩和琥珀 S 脊线修改实际蒙皮模型。四张 512×512 色彩/凹凸纹理在初始化时生成，动画期间不重绘；色彩图使用 sRGB，凹凸图保持线性。纹理含 mipmap 约 5.33 MiB。旧材质生成器已移除，不并行保留两套人物。

概念图不能直接替代可从任意角度观察的三维网格。当前交付仍是程序化建模/纹理的近似实现，不是参考图级高精度扫描或逐像素还原。图二重复关键帧、交叉腿不作为正确运动轨迹；连续动作沿用已验证全身动作及方向重定向。

实际画面：`ui-implementation/c-suit-model-review.png`；六动作八角度可播放页：`ui-implementation/c2-character-preview.html`，使用游戏同一源代码。视觉复查发现并修复小腿护甲与布料穿插、后脑密封球过大。仍须检查复杂坡面/所有运动姿态，不能将几张截图当作全面美术验收。

## 优化与不变项

- 角色闭合矿壳细分深度从 2 减到 1，织物纵向密度调整到约 18mm，保留原始轮廓采样与肘膝褶皱；角色检视上限收紧至 45,000 三角。最终蒙皮按完整顶点记录合并索引，UV/法线/权重不同的顶点不焊接，不跨材质或骨骼硬边合并。
- 岩石最终以 768m 格子分批绘制，使用各块包围体进行视锥剔除。初始 256m 方案增加到 238 次绘制，768m 为 161 次，基线为 138 次；减少三角形不必然抵消新增提交开销，因此调整剔除粒度。原世界坐标、颜色、法线、索引绕序逐项验证一致；跨界岩石整体归属一块，不裁切、不移走、不改变碰撞。没有用距离删除远处岩石。
- 3D 渲染比例在 0.65 到 min(DPR, 1.25) 自动调整，有初始化热身、24帧统计窗口、迟滞恢复与2秒调整间隔；暂停间隔不计慢帧。降低比例会降低3D锐度，但文字/UI保持CSS原分辨率。身体移动、体力时钟和碰撞不跟随分辨率变化。
- 动画缓存已归一化的源帧，零权重片段不再取样，足部 FK 只算腿链，跳过待机/飞行中的无用姿态。优化前后姿态/触地轨迹在 1e−8 量化精度一致，不通过降动画帧率制造“性能提升”。
- HUD 状态按钮与百分比只在显示值变化时重建子节点，减少重复 DOM 分配。

## 性能证据及边界

`node tools/profile-locomotion.cjs <标签>`：1440×900、独立 headless Chromium、同一出生点第三人称前进，采样120个真实帧并丢弃最初10个。全部原始 `ui-implementation/locomotion-profile-*.json` 保留，不覆盖中间尝试。历史采样未记录真实 GL 驱动，不能认定是软件或硬件渲染；追加 verified 已补齐该次采样驱动记录，不能据此追溯认定旧基线驱动相同。

| 记录 | p50 帧耗时 | p95 帧耗时 | 解释 |
|---|---:|---:|---|
| [before](ui-implementation/locomotion-profile-before.json) | 416.7 ms | 433.4 ms | 基线，138 次绘制 |
| [after](ui-implementation/locomotion-profile-after.json) | 299.9 ms | 366.7 ms | 未接岩石分块的中间版，不能作最终改善证据 |
| [tuned](ui-implementation/locomotion-profile-tuned.json) | 383.3 ms | 483.3 ms | 最终 768m 分块方案，161 次绘制 |
| [verified](ui-implementation/locomotion-profile-verified.json) | 349.9 ms | 433.3 ms | 最终方案独立复测，记录真实 GL 驱动 |

verified：最大帧耗 450 ms，内部比例 0.65，161 次绘制 / 379,840 三角形；GL 为 ANGLE Google Vulkan SwiftShader Device (Subzero) / SwiftShader driver，确认该次无头测试使用软件渲染。它只证实本测试环境原生渲染耗时占主导，不代表用户设备有驱动问题；旧基线无驱动记录，不能事后认定同驱动，更不能承诺实机改善比例。最终 tuned 与 verified 的差异也应保留为波动，而非挑选较好采样掩盖长尾。

最终 tuned 的 P95 比基线更差，结果波动，不能宣传“最终提升28%”，也没有证明实机流畅或稳定60FPS。中间 after 包含动态分辨率下降至0.65的取舍，不是同内部像素分辨率下的纯几何收益。采样涉及动态自适应过程，不能把整段中位数当作最终稳定画质帧率；仍需在用户常用浏览器、显卡和明确驱动记录下重复验证。

`node playable/tests/gait-benchmark.mjs`：Node CPU微基准，6000次混合步态调用中位数 99.990→56.839ms（约降低43%）；单次原本仅微秒级，不是这次严重帧耗的主要来源，也不代表FPS提高43%。

全量规则：253/253通过。`npm run test:feature -- movement` 包含动作、索引网格/闭合表面、岩石不变性、动态分辨率边界和14项相关浏览器场景；此前主动停止的门禁不计通过；最终代码 npm test 253/253 通过（20.4 秒），修订后单次 movement 门禁规则 119/119、浏览器 14/14 通过（690 秒），状态 FEATURE_PASSED_NOT_RELEASE，前后指纹一致，详见 HTML5_VERIFICATION.md。119 项为全量子集，不额外相加。构建和预览已更新。发布全流程和真实设备帧率不在本轮结论内。

1. 刷新游戏，核对 C2-ASSET-PERF-20260908，再继续原存档。
2. V 切第三人称、C 开启慢走；检查胸甲、背甲、头盔与小腿正背侧面，再连续前后左右走。

4. Tab打开/关闭、Space起飞着陆、驾驶再下车；文字应清晰、按钮可点，体力与能量规则不变。
5. 使用实际3D检视页的播放/暂停/单步比较动作；照片级服装质感和目标设备流畅度仍需人工验收。
