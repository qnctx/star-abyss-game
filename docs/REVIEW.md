# 代码审查（唯一维护文档）

> 最后审查：2026-09-05
> 审查基线：`main` 当前工作区
> 范围：HTML《静默回声》真实三维改版；Godot 既有变更保留

## 当前结论

此前“第一视角地表”的实现仍依赖坠毁舰背景图片和二维投影，无法满足真正跑进残骸的需求；测试通过只证明旧规则运行，不能证明空间体验正确。当前已换成离线打包的 Three.js 单运行时，人物坐标、地形、结构墙与交互距离采用同一米制世界，主线可从着陆点连续走到船舱并完成返回。

优点：主线围绕证据调查与实体中继谜题闭环，黑匣子返回后续接地表实测与回声源隔离；地图标点、方向导航、实体岩石和避障第三人称与同一世界状态相连。运行时移除了不相关塔防/血清/航线；领域状态、移动和 UI 分离，旧正式存档隔离保留，旧通关进度可迁移到后续调查。风险：程序化美术仍是原型质量，6 km 地表只在残骸、两处异常与地下遗迹集中内容，尚需真人评估跑步手感、长距离节奏及硬件性能。不能将旧 110 项测试或 Godot 测试数量计作本次新版验收。

本次规格及真实复验步骤见 `HTML5_PROTOTYPE.md`、`HTML5_VERIFICATION.md`。

## 以下为重做前审查结论（历史，不代表当前实现）

项目的最大优点是已经形成真实连通的“迫降探索 → 采集/建造 → 点火坚守 → 星图选线 → 深空驾驶 → 霜环星落地”纵切，规则集中、存档有版本兼容、测试接口与正式存档隔离。四个关键界面现已按 Image 2 方向完成高分辨率场景、终端式 HUD 和真实功能的一体化落地，不再只是把概念图压在旧界面下面。

本轮在既有问题修复之上补齐第一人称地表视锥与分析、真正沿视角运动的地表控制及连续世界锚定岩面光流，并把跑步步态从地面/实体/远景投影中拆出，只由手持工具承担身体节奏，修复“整块地面上下浮动”的视觉错误。工程旋转/吸附/页内物流、航线预选确认、护盾/姿态/牵引冷却等驾驶舱遥测也已落地，目标双重锁定和货舱资源格挤压已清除。输入层建立了游戏、Modal、标题页的上下文边界，并补上焦点圈定、切后台暂停和缩放后首次点击坐标刷新。当前 Node 全量 110/110、真实 `file://` Playwright Chromium 12/12 通过；桌面与 768px 四屏截图、静止/W/A 三张移动对照图均从真实页面重新生成。Godot 本轮未改动，沿用最近一次系统测试 463/463、独立逻辑测试 31/31 与主场景 2 帧 smoke 通过记录。

## 做得好的地方

- 核心配置集中在 `playable/js/config.js`，状态、规则、世界、建筑、战斗、远征和存档按领域拆分，测试可以绕开渲染直接验证规则。
- `?test=1` 不读写正式存档，能够安全注入测试状态；E2E 覆盖真实按钮、面板、Canvas 点击和响应式布局。
- 关键 UI 不再只是装饰：视锥目标、工程资源与旋转足迹、航线预选、舰船模块、护盾、航速姿态、深空回收/推力状态都与玩法数据相连。
- 地表相机采样已拆成无副作用纯函数；渲染器不再反写角色朝向，近景地表光流会区分前进、后退与横移，低帧采样、读档重置和安全裁切均有回归覆盖。
- 输入生命周期边界更完整：Modal 阻断游戏输入并圈定焦点，关闭后恢复到合理焦点；按住的方向键不会跨面板“复活”，切后台暂停模拟，交互控件保留原生空格/方向键行为。
- 存档对白名单字段做迁移和清洗；旧 schema 仍可兼容，深空读档保留连续危险而不是降低难度。
- HTML5 规格原型与 Godot 正式实现的职责已在文档中明确，避免继续混用 Unity/Godot 路线。

## 仍存在的不足

- HTML 世界、敌人和建筑仍使用线性数组与圆形距离判断；长时间高密度对象下没有空间索引或障碍寻路。
- Godot 建筑成本、标签和实例化规则仍分散在建造、科技和建筑脚本中，尚未与 HTML 的集中配置建立单一数据源。
- Godot 炮塔、减速场、氧气站等仍有高频 group 查询路径；当前规模可运行，但扩容前应缓存引用或按固定间隔查询。
- 本次输入/焦点与地表光流新增 E2E 尚未执行；既有 Chromium 结果不能替代本轮复验。Chrome/Edge/Firefox 矩阵、触屏控制、音频、跨设备存档和真人 30–45 分钟长局仍未覆盖。
- 四张静态高分辨率场景已把构图与氛围拉到一致方向，HTML 地表也补上了轻量近景视差与步态，但动态实体、材质动画、粒子和声音仍是原型级，最终品质仍需在 Godot 正式版本完成。

## 下一验证顺序

1. 先人工复验地表光流方向、Modal 输入隔离/焦点、切后台暂停和缩放后首次点击，再进行固定种子 30–45 分钟真人通关，包含失败重开、点火 180 秒、深空读档和应急迫降回收。
2. 执行 Chrome、Edge、Firefox 与断网 `file://` 启动矩阵，补充 621px、800px、1440px 临界截图。
3. 以性能采样为依据处理 Godot 高频 group 查询，并把建筑配置逐步集中化。
4. 按 `docs/HTML_GODOT_CONTRACT.md` 对齐 Godot 的玩家可观察行为，不重复已由 HTML5 证明的规则探索。
