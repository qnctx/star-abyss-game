## 3D 正式版本交接规则

HTML5 原型是**行为规格与交互验收场**，不是正式画面目标；它保持俯视 2D，才能低成本地验证资源、距离、敌人、存档和 UI 规则。正式 Unity 3D 版本不需要从头重复本台账中已经“真人通过”的玩法测试。

- 直接继承：资源数值、扫描/采集/建造/回收规则、敌人奖励、存读档语义、区域限制、快捷键意图与失败提示。
- Unity 只做“实现一致性复验”：逐项确认 3D 版本是否仍遵守对应已通过规则；如果规则没有变，只记一次通过，不重新设计测试。
- 仅新增 3D 专属验收：镜头与遮挡、地形/碰撞、点击射线命中、单位尺度与攻击半径、动画/特效可读性、3D HUD 布局和性能。
- 若 Unity 阶段主动改变任何玩法规则，才为该条规则开新版本测试记录，并在本台账中链接替代关系。

### F-006/F-010 确认缺陷：空闲炮塔被读档过滤 — 2026-07-12

- 复现证据：用户在画面中同时拥有 2 座炮塔，保存提示明确显示“建筑 2”；随后存档管理却只统计 0 或 1 座，读取后炮塔同步消失，而资源与其他进度保留。
- 根因：炮塔没有敌人时，射击冷却 `timer` 每帧持续递减；空闲超过 10 秒后低于存档校验允许的 `-10`。保存文件中实际包含炮塔，但档位统计与读取清洗把该炮塔误判为无效建筑并删除。炮塔越旧，越先消失。
- 修复：空闲炮塔冷却最低钳制为 0；读取时兼容旧档中已存在的负计时并修复为 0，不再删除建筑。同步恢复 `savedAt` 字段，修复档位时间显示“未知时间”。
- 自动证据：`npm test` 31/31 通过，新增覆盖空闲 120 秒计时不为负、旧 `timer=-120` 存档恢复建筑与保存时间。
- 真人复验：用户确认修复后正常；自动存档与三个手动档位均显示“建筑 2”和真实保存时间，旧档里的炮塔恢复且可继续保存/读取；截图证据 `codex-clipboard-570d592c-60c8-484b-9243-91711a649061.png`；2026-07-12。
- 结论：炮塔负计时导致的读档丢失缺陷已通过；F-010 的多档保存、时间、建筑计数与读取恢复通过。
