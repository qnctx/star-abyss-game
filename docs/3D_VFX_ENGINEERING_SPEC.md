# 3D、特效与工程规范 D2

2026-09-08；依赖 [总纲](DEVELOPMENT_MASTER_PLAN.md)。本文件定义验收合同，不声明现有画面已全部满足。

## 1. 空间、物理与资产

- 米制尺度统一。保留现有坐标约定：Y向上，角色yaw=0朝-Z；资产导入必须转换到项目坐标，不在不同系统重复反转。
- 几何以真实用途设计：人物通道、载具转弯空间、门洞净空、楼梯与可攀爬面先做白盒。破损建筑也需要连接关系，不用随意倾斜板片伪装残骸。
- 模型轮廓、碰撞体、落脚支撑和镜头避障使用同一空间来源；允许简化碰撞，但不能改变可通行性。装饰性碎屑必须有明确高度/尺寸分类，不能视觉巨石却可穿过。
- 除有明确艺术用途的薄片外，重要结构封边、法线正确；不靠全局双面材质掩盖缺面。镜像资产检查绕序、法线、阴影与材质方向。
- 地形渲染与脚底/载具高度采样一致。禁止移动整张地面制造走路、用背景图放大制造接近、用视角贴纸冒充可进入飞船。
- LOD不得改变主要轮廓、碰撞入口与关键弱点位置。区域切换不得让角色落空或重复生成奖励。

## 2. 角色与动作

### 图像分解先于 3D（2026-09-27 用户长期规则）

后续所有新增或重新设计的人物/野怪动作、武技及特效，先用 image 生成对应的详细分解图，再依据图制作 Blender 模型、骨骼动画和引擎特效。通用角色立绘不能代替具体动作分解；不能先做程序动作，再补一张概念图当作依据。

- 动作图明确同尺度与地面线、关键姿势/相位、支撑脚和重心、手脚运动路径、发力/接触/收势；循环动作包含完整左右周期，技能包含起手、释放及恢复，必要时补正面、侧面、背面和手脚细节。
- 特效图明确蓄势、释放、飞行/持续、命中、落空、中断及消散的分镜，并标出人体/野怪释放部位、方向、范围和与动作对齐的时刻。
- 先检查生成图的解剖、左右交替、支撑关系和阶段连贯性，不机械照搬生图错误；通过设计检查后再做 3D。保存图、提示词和对应资产/片段清单。
- 在真实 Godot 场景按正常时间对照分解图验收最终蒙皮、动作与特效，检查连续前侧后视和起停/打断；关键帧截图及参数达标不能替代连续表现验收。

这条规则作为后续制作的默认流程；生成数量与费用仍按明确的任务/批次范围执行，不由流程偏好推导无限生成授权。

视觉锚点：同一件C探索服，柔性灰白织物、非对称深色矿壳、金色脊线；自然人体比例，避免机械方块肢体。头盔、防护与裸露范围按环境要求，不随技能等级无理由变成无防护服装。

保留一套权威骨架/蒙皮与动作驱动。待机、走、跑、冲刺、转身、起停、起飞、落地、驾驶、技能动作按显式状态混合；任何接管结束均回到正确移动状态。不能两套动画控制器同时写同一关节。

角色根位移由移动/碰撞模拟负责；动画只表现已批准运动。足部IK采用有限修正，超预算应调整动作/站姿，不能无限拉伸四肢。施放时说明可移动、可转向、可中断的窗口；这些规则由技能状态机决定，不藏在动画时间回调里。

动作验收必须连续看：正背左右、斜坡、近墙、四方向起步、急停、落地、技能中断、低帧率。单张好看截图不算动作通过。沿用素材前记录来源、许可、修改步骤；不把概念图称为已绑定模型。

## 3. 材质与光照

材质库统一管理织物、金属、矿壳、尘土、岩石与能量表面；避免每个技能各造一套不一致的颜色/亮度标准。按项目渲染管线统一颜色空间与曝光。

深色不等于没有细节；暗区仍应能分辨路径与实体。发光材质不能替代全部照明。动态灯要有距离、生命周期和数量限制；禁止每个粒子都创建灯光。

环境参数定义介质、重力、风、尘土与照明；不同区域可以有不同配置，不能全局写死“所有星球一样”。不在本阶段承诺流体、完整破坏或天体力学模拟。

## 4. 技能特效合同

每项技能都有 prepare → release → sustain → hit/interrupted → dissipate 五类表现，允许无持续阶段，但中断/取消必须有退出路径。

|通道|用途|约束|
|---|---|---|
|三维网格|屏障、发生器、波面|有朝向与厚度感，遮挡正确|
|粒子|喷流、尘屑、火花|有上限、生命周期；落点材质不同|
|拖尾|短时运动路径|采样真实轨迹，不跨传送/菜单接成巨线|
|表面命中|局部共振、灼痕|贴实际命中法线，避免悬空或穿模|
|短时光照|释放和命中的空间照明|限制数量与距离，及时回收|
|音效|来源、强度、接触反馈|与事件同步，按介质/服装传导设计|

模拟先结算，再发布效果事件；VFX不修改血量、位置、熟练度或冷却。范围、角度、持续时间来自同一技能定义；粒子大小不得冒充真实伤害半径。近距离第三人称效果不得遮住整个人物，第一人称避免遮挡准星和威胁前摇。

五境界使用同一EffectProfile体系逐层增强结构、控制精度与短时连携标识，不复制五套独立业务逻辑。颜色不是唯一等级标志，兼顾低画质和辨色差异。

屏障专项：正面/背面/侧面检查，入射点涟漪，剩余强度可读，破裂正确消散。闪避专项：喷口绑定角色、轨迹连续、碰墙终止、落地粉尘来自真实接触面。攻击专项：墙体挡住射线与表现，命中只触发一次。

真空场景不生成普通空气烟雾/外部空气爆音；服装接触声可以保留。非真空场景的尘土随地表、风与接触改变。减少闪光、震动、拖尾的设置不得改变玩法结算。

## 5. 性能与资源生命周期

以下为待硬件标定的初始预算，不能作为“已经达标”的宣传：

- 中档目标1080p/60fps（16.7ms帧预算）；最低支持设备目标30fps（33.3ms）。M0必须记录CPU/GPU/内存/浏览器/分辨率/画质后确定实际支持范围。
- 同一参考设备新增单技能表现的帧时间增量先以不超过2ms作为调查阈值；超出需剖析，不以肉眼“好像流畅”放行。
- 测试同时6个短时效果、2个屏障和多次命中；低档减少装饰粒子/灯/拖尾采样，保留范围、前摇、命中与破裂。
- 统计p50/p95帧耗时、draw calls、三角形数、活动粒子、动态灯数、几何/纹理资源计数；是否超预算根据目标硬件复测，不只看平均FPS。
- 同场景连续释放/取消技能200次，再切换区域10次：活动效果归零，资源计数不能持续阶梯增长。JS堆受GC影响，只作趋势辅助，不用单次内存读数证明无泄漏。

效果池复用短生命周期对象；卸载时释放订阅、计时器、几何/纹理/材质引用与音频节点。共享资源由注册表计数管理，不由每个实例随意dispose。截图工具和诊断模式不进入正常帧循环。

## 6. 工程分层与职责

|模块|负责|不得负责|
|---|---|---|
|世界/区域|实体布局、环境、加载/卸载|技能经验与界面按钮|
|移动/碰撞|实际位置、扫掠、支撑、镜头约束|按特效轨迹直接传送角色|
|能力模拟|资格、施放状态、消耗、冷却、目标与结算|DOM、粒子对象|
|成长|消费有效事件、条件、突破事务|每帧猜测按键是否有效|
|表现|骨骼、材质、粒子、灯、音|修改权威进度|
|UI|呈现状态、提交明确命令|复制一份伤害/升级公式|
|存档|版本化、校验、迁移、恢复|保存WebGL和DOM对象|

当前main.mjs逐步收敛为装配入口；scene.mjs逐步拆为有用途的场景组件，不进行无目的“每个函数一个文件”。纯规则保留可在Node中测试；浏览器适配层负责输入/渲染。新能力先配置与规则，再表现，不从HTML按钮回调直接改世界。

建议事件通过明确接口传递，不建立到处可写的全局事件袋。相同参数只有一个配置来源；定义固定时间/秒数语义，避免帧率变化造成不同消耗。主模拟唯一时钟，暂停冻结，恢复不补算漏帧奖励。

## 7. 冗余代码与资源清理规程

先列清单，再替换，再删。没有引用搜索/构建/回归证据，不得只凭名字判断“旧文件没用了”。

1. 盘点入口、import、动态路径、HTML引用、构建脚本、测试夹具与存档兼容读取。
2. 为待替换模块标注当前消费者及新模块；同一功能只允许一个正式驱动，不长期保留v1/v2同时运行。
3. 新实现接入并通过相关回归后，删除被替代逻辑、废弃UI入口和确认为无引用的发布资源。
4. 重复资源先检查许可/原始素材/编辑源用途。可复现源文件和许可证不等于冗余。
5. 移除临时调试日志与生产热路径中的诊断；保留受控测试接口，不暴露作弊入口给普通存档。
6. 构建产物来自构建，不能手写产物补丁。必要迁移、回归测试、源资产和许可证必须保留。
7. 不清理用户无关改动，不删除独立Godot实现。大范围删除列明目标、替代位置与恢复方式，范围不清先确认。

“无冗余”的完成定义：没有并行废弃实现、无效入口、无引用发布资源、重复公式与失控订阅；不是文件越少越好。
