# 车辆坡面独立物理验收

日期：2026-09-16。测试文件：`playable/tests/vehicle-slope-audit.test.mjs`。测试工作仅新增测试/报告，未修改产品、未发布。

## 首轮结果：8 PASS / 2 FAIL

实际复现两个产品缺陷，已反馈主控：

1. 滑坡速度帧率依赖。真实 `stepMobility` 在同一 1.15 梯度坡面无油门运行 1 秒，30/60/120Hz 分别得到 4.1667 / 10.0833 / 22.0417m/s。`signedSpeed` 使用包含上帧滑坡分量的 player.vx/vz，再把固定滑坡速度叠加并写回，造成按帧累加。台阶/坡面通过正式 layout 扩展接口注入，未替换物理实现。
2. 落崖存档瞬移。真实车辆驶离 4m 台阶，`grounded=false` 时保存 y=3.9980556m；serializeMobility / restoreMobility 后 y=0，直接传送到崖底。新接触状态被序列化但没有被恢复。

通过项目：

- 原实际地形 (-140,20)、(220,40)，0 / 0.7 / π/2 朝向的车体全几何顶点与 terrainHeight 实测不穿山；使用真实 createSkimmer / Three 矩阵，只 stub 仪表 Canvas 的文字绘制，因为 Node 无 DOM。
- 原地形约 .69 坡度连续上坡、下坡，支撑高度一致、不穿地。
- 原地形约 1.15 坡度松开油门向下滑，不保持悬停。
- 驶离 4m 台阶连续重力下落、着地；未把第一帧直接吸到地面。
- 未批准的向上台阶不由垂直接触函数凭空抬升。
- 原地形驾驶耗电符合实际路程；持续油门时按住刹车可停下。
- 原存档缺少接触字段时，位置、修复标志、电量与驾驶状态兼容。

热启动 1000 步静止物理约 8–9ms（约 0.009ms/步），不包括 Three 渲染、浏览器、地形流送，不等同 FPS 承诺。
