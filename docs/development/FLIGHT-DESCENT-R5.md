# 飞行下降手感 R5

## 变更

持续按住 `C` 下降时，下降目标速度由原来的 `max(2, AGL × 0.18)` 改为连续的制动距离包络：`min(65, max(2, sqrt(2 × 6 × AGL)))` 米/秒。`AGL` 是当前脚下地形高度，不是海拔；因此低空会随剩余落地距离平滑减速，较高处仍受原有 65 米/秒上限约束。6 米/秒² 是目标速度包络的落地减速度，原有 90 米/秒² 垂直加速上限和 220 米/秒² 超速制动上限保留。下降速度已经超过包络时使用后者及时收速，包括能量耗尽的受控下降。

没有修改 `C` 输入映射、起飞与上升、水平飞行、2000 米相对地面高度上限、碰撞扫描、存档或地面移动。遇到陡坡，原有路径扫描仍会阻止穿过地形；安全接地后飞行结束，不反弹。

## 浏览器初次对比

同机独立 Chromium、真实按住 C：旧版 30 米第一/第三人称落地约 11.31/11.37 秒，候选约 3.16/3.68 秒；200 米第三人称由 22.26 秒缩短到 8.39 秒。位置单调下降，安全接地，2000 米初段仍约 65 米/秒，松 C 后恢复悬停。

候选 200 米第三人称帧耗时 P95/P99 仍为 33.4/50.1ms，超过 33.34ms 的帧占 7.1%（旧版 4.4%）。因此本次曲线调整只能证明下降时间改善，不能认定掉帧已解决。报告位于 `artifacts/r5-baseline/report.json`、`artifacts/r5-candidate/report.json`，候选包 SHA256 为 `24119da24855673e74ce425a6197a8cace928ea0ba4ed67b0f431185477eddc5`。

## 人工复验步骤

使用独立测试入口 `http://127.0.0.1:4173/star-abyss.html?testLab=1`，不会升级或重置普通存档。普通 L0 存档的旧助推不用于验收元婴自身飞行。按 F2，分别选择 30 米及 200 米高度，跳转后点击“恢复键盘飞行”，关闭面板并点击画面。按住 `C`，观察离地高度和实际下降：高处加速、近地连续减速、接地后停止；松开 `C` 应减速后悬停，接近地面时可能先安全着陆。按 V 切换视角复测。随后沿上坡或山脊斜向下降，确认不会穿地，遇阻可移开方向键继续垂直安全降落。能量耗尽时的自动下降由 CPU 回归覆盖。

## 下降期间的渲染比例选择

总控将渲染比例上限设为 1.0 的诊断中（测试中仍自适应到 .95），200 米下降慢帧为 12/485（2.5%）；原 1.25 候选为 29/410（7.1%）。像素量对该场景有可观影响。因此最终只将设备 DPR 上限从 1.25 调到 1.0，仍保留原 0.9 下限；高 DPR 屏幕最多以 CSS 1× 渲染，UI 的 CSS 大小和游戏模拟不变。

曾试验连续两个慢窗、每次降 0.1 并在冷却期采样的新调度器，但 R5b 200 米下降仍有 27/405（6.7%）慢帧，收益不明确，**未纳入最终实现**。最终版恢复正式源文件原有的 3×60 帧判断、每次 0.05 调整、4 秒冷却、8% 漏帧阈值、CPU 瓶颈保护和缓慢恢复。

CPU 回归命令：

```cmd
node --test playable\tests\render-budget.test.js
```

结果：6/6 通过。原五项压力、CPU 峰值、冷却和恢复测试保留并按 1.0 上限更新预期；新增设备 DPR 1.5/2 均限制到 1.0 的断言。
