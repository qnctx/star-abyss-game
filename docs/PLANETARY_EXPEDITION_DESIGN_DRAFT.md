## 1. 一句话定位

人类已经进入星际探索时代。玩家所属的远征飞船在前往下一颗目标行星途中穿越陨石群，紧急规避时推进、姿态控制和导航模块受损，被迫降落在一颗陌生星球。玩家必须在严酷环境中建立前线设施、修复飞船，并在发动机点火的最后防线中撑到重新起航。

这里的“动能损坏”建议在设定中表述为：**陨石撞击导致飞船的动能推进／姿态控制总成失效**。这样保留“动能”这一科幻感，同时避免把“动能”本身当作可损坏的零件。

## 2. 本次二创的核心原则

1. **不推翻已通过玩法。** 当前的扫描、采集、四区域、适应、建造、防守、存档、信号台和坚守结局都保留。
2. **每个旧系统都要有新的叙事职责。** 不能只把“基地”文字替换成“飞船”，而要让氧气、护盾、研究、信号和战斗都服务于修船。
3. **一颗星球是一段完整远征。** 当前地图先作为第一颗行星，而不是一开始就做无限星球生成。
4. **修复不是额外刷材料清单。** 每个飞船模块恢复后，应立即带来可感知的能力或阶段变化。
5. **离开星球不是“救援撤离”。** 最终是玩家亲手让自己的船重新点火、起飞，并把下一颗行星作为后续远征的目标。

### 2.1 已确认的方向

- 飞船定位为**科研远征舰 + 必要的军事自卫能力**：它不是战舰，武器、防护罩和无人炮塔的职责是保护勘探任务与舰体，而不是征服星球。
- 远征是**多星球连续战役**：飞船起航后打开星图，选择下一段航线；每颗行星都有独立设定、独特主机制和专属收获。
- 深空不是纯加载画面：航行中可选择安全航道、资源绕行或高风险捷径；陨石群需要玩家亲自操控规避，也存在主动采集深空漂浮资源的机会。
- 飞船损伤会被长期记录。技术足够好时可按计划抵达目标星球；损伤达到临界值时，飞船会被迫驶向**星图上最近且可安全着陆的预设星球／中继点**，而不是随机凭空生成一颗星球。
- 星球是手工设计的，不做“换色地图”的无限随机生成；变化来自航线选择、抵达方式、深空事件、局部资源与可选目标。

## 3. 世界观骨架

### 3.1 人类为何探索宇宙

地球仍然存在，但已经不再是唯一家园。多个国家、企业和科研联盟共同资助“远航计划”：在可居住带、资源富集带和异常天体之间建立长期航线。玩家所属的不是殖民军队，而是一支小型先遣勘探队；任务是验证行星环境、回收异常物质，并为后续舰队绘制安全航图。

### 3.2 第一颗行星：当前地图的身份

暂定名称：**N-47「裂环星」**（名称可讨论）。

它是一颗生态与地质都不稳定的边缘行星。迫降地点附近形成四个彼此相接的环境带：

| 当前区域 | 行星内解释 | 已有玩法职责 |
| --- | --- | --- |
| 坠毁区 | 飞船坠落形成的残骸盆地；大气相对稳定 | 开局、飞船停泊地、基础资源与教学 |
| 极寒区 | 长夜冰盖与低温裂谷 | 高氧耗、寒冷环境与低温适应 |
| 熔岩区 | 活火山裂隙和地热矿带 | 高氧耗、建筑高温侵蚀与稀有材料 |
| 重力异常区 | 局部重力潮汐／异常矿脉带 | 移动受限、高氧耗与高风险资源 |

原型里的地下资源、能量核心、虚空晶体和蓝图，可统一解释为这颗行星的深层矿物、旧远征遗留物或未知文明残片。

### 3.3 敌对生物为何攻击

迫降产生的热量、噪声、辐射和夜间照明会吸引本土掠食／清道夫生物。基地与野外设施持续发出的能量信号，会让它们把这些设施视为威胁或可捕食目标。

这样可以自然解释已有夜袭、炮塔、防护罩和建筑受损规则，而不需要改掉已通过的战斗逻辑。

## 4. 核心循环：从生存改为修船

```mermaid
flowchart LR
  A[迫降：飞船生命维持在线] --> B[探索区域 / 扫描采集]
  B --> C[部署前线设施 / 提升适应]
  C --> D[研究未知材料 / 修复飞船模块]
  D --> E[建立导航阵列 / 定位起航资源]
  E --> F[主推进点火坚守]
  F --> G[飞船起航：解锁下一颗行星]
```

玩家在每一颗星球的基础节奏仍是：

1. 保住飞船和自身氧气；
2. 扫描并采集当前可安全进入区域的材料；
3. 建造前线设施，把活动半径推向下一环境带；
4. 研究、适应与防御共同打开高价值区域；
5. 把取得的关键材料投入飞船模块；
6. 完成起航前的最终防守，离开该星球。

## 5. 旧功能的新身份（保留，但改得有意义）

| 当前功能 | 行星远征版名称／解释 | 对主线的作用 |
| --- | --- | --- |
| 基地核心 | **远征飞船「曙光号」**（暂名） | 飞船耐久就是失败条件；返回舰体范围立即补氧；储物舱是货舱 |
| 玩家 | 舱外勘探员／远征队最后一名可行动成员 | 在飞船与前线设施间执行探索、采集、防御 |
| 炮塔 | 舰载自动防御炮塔 | 守住舰体、关键设施与起航窗口 |
| 氧气站 | 前线生命维持中继站 | 让勘探员能在远离飞船处快速补氧并建立补给线 |
| 护盾发生器 | 舰体偏导护盾投射器 | 保护飞船，抵消夜袭压力 |
| 太阳能板 | 外置能量采集阵列 | 为研究、通信和起航准备供能 |
| 研究站 | 行星分析实验室 | 把未知材料转化为蓝图／模块维修方案 |
| 减速场 | 重力锚／干扰场 | 延缓敌群，保证防线和点火阶段 |
| 信号台 | 深空通信与导航阵列 | 扫描轨道、校准航图、定位遗失的飞船部件 |
| 血清适应 | 舱外环境适应注射剂 | 让勘探员可安全进入更极端区域 |
| 资源缓存 | 坠毁货舱、旧探测器或异常遗迹 | 提供维修材料、蓝图与剧情线索 |
| 撤离坚守 | **主推进点火坚守** | 飞船系统启动时抵御被信号吸引的敌群；成功后起航 |

## 6. 飞船维修：建议的四模块结构

这一层是新主线，但应在后续逐步加入，不能一次把四个纯进度条堆到 UI 上。

| 模块 | 初始状态 | 修复来源／关联已有玩法 | 修复后的即时变化 | 叙事意义 |
| --- | --- | --- | --- | --- |
| 生命维持与货舱 | 勉强工作 | 基础资源、氧气站、货舱管理 | 保持现有即时补氧与储物能力；作为开局已半修复模块 | 飞船还能让玩家活下去 |
| 防御与外壳 | 受损 | 炮塔、护盾、维修、防守 | 提升飞船抗袭与最终点火防线容错 | 让舰体经得起夜袭和点火震动 |
| 导航与通信阵列 | 离线 | 研究站、蓝图、信号台、25/50/75%缓存 | 逐步显示行星信息、维修坐标与下一跳候选 | 玩家知道该往哪里飞 |
| 动能推进与姿态控制 | 严重损坏 | 高风险区域资源、能量核心、最终救援坐标缓存 | 解锁“主推进点火” | 这是离开当前星球的硬条件 |

### 推荐的阶段感

- **开局：** 船还能供氧、存货、复活，但不能升空。
- **中期：** 通过研究和信号阵列发现：真正缺的不是“求救”，而是散落在行星各处的推进／导航部件。
- **后期：** 通过高风险区材料修复推进系统，开始起航倒计时。
- **终局：** 主推进充能会产生强烈热源和电磁信号，敌袭加剧；坚守 180 秒后飞船离地，进入航行结算。

## 7. 对现有 Signal 玩法的重写建议

当前“信号台推进 0% → 100% → 救援坐标缓存 → 撤离坚守”的行为是好的，不必推翻。建议只改其叙事和最终目的：

| 当前节点 | 行星远征版解释 |
| --- | --- |
| 0–25% | 通信阵列重新接入飞船黑匣子，定位前线货舱 |
| 25% 缓存 | 回收「工程补给舱」：基础维修材料 |
| 50% 缓存 | 回收「导航数据芯片」：蓝图与航图碎片 |
| 75% 缓存 | 回收「推进中继件」：高能部件与防线补给 |
| 100% 缓存 | 定位「主推进校准核心」：回收后才能点火 |
| 180 秒坚守 | **点火窗口**：舰体预热、姿态矫正、主推进启动；撑住即起航 |

因此，原型不再是在等外部救援，而是在利用信号阵列找回自己飞船缺失的关键部件。

## 8. 建议新增、但不立刻实现的玩法

以下按优先级分层，避免范围失控。

### P1：第一颗星球的“修船目标层”（优先）

- 飞船维修面板：只显示四个模块、缺失材料、修复收益和当前阶段。
- 把当前 Signal 最终目标文案改为“主推进校准核心／点火”，不改变其已通过的交互链。
- 在无线电日志中增加简短的坠毁记录、区域勘探记录和模块线索。
- 顶栏目标从“建造第一座炮塔”逐步过渡到“修复导航阵列”“准备主推进点火”。

### P2：有选择的行星探索（第二阶段）

- 每个区域设置一个**可选异常点**：不是额外必刷材料，而是有风险、有回报的探索决策。
- 例如：熔岩区给推进耐热部件，极寒区给低温导航晶体，重力区给姿态校准数据。
- 行星日志提供世界观，而非大段文本；每次回收只得到 1–2 句可信线索。

### P3：第二颗及以后行星（第三阶段）

- 起航后显示简短航行结算：带走的货物、完成的可选目标、解锁的永久蓝图。
- 下一颗行星用**不同主规则**制造新鲜感，例如：酸性风暴腐蚀、低光能量稀缺、移动沙海、无线电干扰。
- 只继承合理的长期进度：研究蓝图、少量货舱材料、船体模块状态；不应把整座地面建筑带去下一星球。

## 9. 当前第一颗星球的推荐任务线

1. **迫降求生**：确保飞船生命维持、建造第一座自动炮塔。
2. **建立补给半径**：用氧气站和扫描器进入附近区域，回收基础材料。
3. **环境适应**：制作血清、进入极寒／熔岩／重力异常区，取得特殊材料。
4. **重建科研能力**：研究站产出蓝图，解锁防御与高级设施。
5. **校准航图**：部署深空通信与导航阵列，推进信号并回收四个关键缓存。
6. **修复推进总成**：在维修面板中完成最终模块。
7. **点火起航**：回收校准核心，坚守 180 秒，飞船离开裂环星。

这条线能让现在所有已验收系统都有一个清楚的“为什么”，同时没有强迫玩家做无意义的新重复劳动。

## 10. 体验与 UI 原则

1. **名称渐进替换。** 下一轮只把“基地”替换为“飞船／远征飞船”，不要同时重做所有界面。
2. **维修状态不常驻霸屏。** 使用一个可打开的“飞船状态”面板；顶部仅显示当前主目标和一条关键模块提示。
3. **星球信息在需要时出现。** 进入区域时显示地质/风险短条，详细资料放到既有可翻页说明书和无线电日志。
4. **终局的视觉目标明确。** 点火时飞船核心应有充能、耐久、倒计时和敌袭来源反馈，不能让玩家误以为又是普通夜袭。
5. **已通过交互继续保持。** 任何叙事改名不能破坏快捷键、范围提示、存读档、跨区限制与既有自动测试。

## 11. 已确认方向与仍待决定的内容

| 议题 | 当前结论 |
| --- | --- |
| 飞船定位 | 科研远征为主，带必要的军事自卫能力 |
| 战役结构 | 多星球连续远征；修复、起航、选航线、继续探索 |
| 跨星继承 | 保留蓝图、飞船模块和有限货舱物资；地面设施不直接带走 |
| 深空玩法 | 有手动操作、资源采集、陨石群、航线风险和飞船损伤 |
| 强制迫降 | 损伤达到临界时，落到星图上最近的可达预设星球／中继点 |
| 星球设计 | 手工预设，各有主机制；流程顺序与抵达状态不固定 |

还需要之后决定的只有细节，而不是大方向：飞船正式名称、第一批做几颗星球、深空阶段是否在首版加入太空敌人（本草案建议先不加）以及最终远征终点是什么。

## 12. 建议的落地顺序（确认设计后）

1. **术语与目标层**：基地改名飞船、Signal 改为导航阵列、撤离改为点火；不改变已验证规则。
2. **维修面板与阶段目标**：让每次收集、研究和建造都能对应到飞船修复。
3. **缓存与无线电叙事**：把四个里程碑变成四个飞船部件线索。
4. **起航结局表现**：把现有坚守成功后的结果改为飞船起航结算。
5. **第二颗星球设计**：在第一颗星球完整通过后，再设计差异化环境与跨星球继承。

## 13. 深空航行与航线选择

### 13.1 星图不是传送菜单

飞船离开行星后进入星图。星图由手工设置的节点和航线构成，而不是随机刷出无名星球：

| 节点类型 | 用途 | 玩法价值 |
| --- | --- | --- |
| 预设行星 | 可登陆的完整关卡 | 有独立环境、主目标、资源和剧情 |
| 中继点 | 安全补给／临时维修位 | 损伤严重时的缓冲，不做完整地面关卡 |
| 残骸带 | 可选深空采集点 | 用风险换材料、数据或推进剂 |
| 陨石群 | 主动操控规避的危险航段 | 测试驾驶与飞船损伤管理 |
| 异常信号 | 小型抉择事件 | 给出捷径、情报或可选风险 |

每一条路线都应在选择前明确显示：目标、预计消耗、主要风险、可能收获、当前飞船是否能安全完成。玩家不是“猜盲盒”，而是在信息不完整但可判断的条件下做远征决策。

### 13.2 一段航行的节奏

一段深空航行控制在 **30–90 秒**，不抢走地面探索的主戏份。

1. 在星图选择安全直航、资源绕行或高风险捷径。
2. 进入局部航行画面；常规航段可自动巡航。
3. 遇到陨石群、残骸带或异常时，玩家自行操纵飞船的横移、转向、加速和减速。
4. 玩家可选择专心规避，或减速进入采集窗口，使用牵引／采矿设备回收漂浮材料。
5. 到达目标前生成一份航行报告：收获、碰撞、模块损伤、航线偏移和是否需要应急着陆。

**操作原则：** 手动驾驶要有实际收益，但不应成为反应能力不高的玩家无法通关的门槛。安全航道和航行辅助保证低风险抵达；精确手动规避、主动采集和危险捷径则奖励更高效率与额外资源。

### 13.3 深空资源

建议新增一个和地面“能量”分开的资源：**航行反应质／推进剂**。现有能量主要供给太阳能板、研究站、信号阵列等地面设施；把它直接当作星际燃料会让经济含义混乱。

深空可回收的对象主要是金属碎片、冰晶、废弃探测器、反应质云和古老航标数据。它们可以提供铁、虚空晶体、能量核心、蓝图碎片或推进剂，但必须在碰撞风险、耗时和导航偏移之间取舍。

## 14. 飞船损伤、失控与应急迫降

### 14.1 四个长期记录的飞船模块

| 模块 | 航行中的表现 | 行星上的后果／维修来源 |
| --- | --- | --- |
| 舰体与生命维持 | 决定撞击承受与舱内安全 | 对应飞船耐久、氧气保障、外壳材料 |
| 动能推进与姿态控制 | 决定转向、制动和能否继续长距离航行 | 对应推进组件、惯性校准材料和高风险区资源 |
| 导航与深空通信 | 决定航线误差、风险预警和可选节点信息 | 对应信号阵列、蓝图、导航数据缓存 |
| 能源与防护 | 决定护盾、深空采集设备和关键系统供电 | 对应太阳能、能量核心、热管理材料 |

每个模块必须显示为 0–100 的清晰状态，并在受损时给出**原因、数值、后果、可维修材料**。绝不只用一句“飞船坏了”让玩家猜。

### 14.2 损伤阈值和玩家选择

| 状态 | 数值 | 规则 |
| --- | --- | --- |
| 正常 | 70–100 | 可按计划航线前进 |
| 受损 | 40–69 | 明确显示性能折损；仍可选择低风险航线 |
| 危险 | 20–39 | 高风险航线锁定或强烈警告；应优先维修或前往中继点 |
| 临界 | 0–19 | 无法安全执行计划长跳；进入最近可达的应急着陆走廊 |

其中以**动能推进与姿态控制**为关键判定：低于临界值后，飞船不应硬飞向远处目标。星图会自动标出最近可达的预设行星／中继点，并让玩家进行短暂的应急操控；未能恢复稳定就进入迫降。

这满足“技术好可以照计划到达、操作失误或连续碰撞会迫降”的目标，同时避免出现“宇宙里突然生成一个最近星球”的不合理情况。每条可选航线在设计上都要有至少一个可达应急节点。

### 14.3 迫降不是失败画面

首次游戏的裂环星迫降是剧情固定事件。之后的应急迫降则是动态后果：

- **按计划抵达：** 带着完整货舱和可选的登陆准备，较快进入该星球主目标。
- **应急迫降：** 指定模块带伤、少量货物可能散落为可回收缓存、初始可用设施更少，但仍可修复并继续远征。
- **无损／轻损驾驶：** 可以跳过非必要的修复停留，直接按照原计划前往目标星球。

舰体归零不建议做永久删档；应回到本段航行开始时的自动存档。这样深空操作有压力，但不会把长期战役变成一次失误就全盘清空的惩罚。

## 15. 预设行星阵列：固定身份，不固定顺序

第一颗星球固定为当前原型地图；之后的星球应按“一个主机制 + 一种专属材料 + 一项飞船收益”设计，而不是把四区数字换色重做。

| ID／暂名 | 抵达条件与环境 | 主机制 | 专属收获 | 对飞船／战役的价值 |
| --- | --- | --- | --- | --- |
| P-01 裂环星 | 剧情首次迫降；现有四区域 | 扫描、适应、前线建造、防线、导航阵列 | 基础维修物资、虚空晶体、首批蓝图 | 修复基础姿态与导航，解锁星图 |
| P-02 霜环星 | 低光长夜冰原 | 太阳能弱、热量与能源调度更重要 | 超导冰晶、低温冷却剂 | 强化导航与能源散热，降低长航行风险 |
| P-03 赤炉星 | 火山裂隙与高热地壳 | 热浪周期、建筑耐热与地热采集 | 耐热陶金、地热核心 | 提升舰体耐热和主推进点火容错 |
| P-04 潮汐星 | 重力潮汐频繁的岩质行星 | 重力窗口改变移动／抛射／部署策略 | 惯性晶核、姿态校准件 | 修复动能推进与姿态稳定器 |
| P-05 雨幕星 | 导电风暴与酸性云层 | 通信受干扰、可见度和远距导航不稳定 | 导电薄膜、天线材料 | 升级深空通信、解锁更远航线情报 |
| P-06 碎轨卫星 | 小型无大气卫星、邻近残骸带 | 外部舰体维修、深空采集与低重力作业 | 反应质、推进校准芯 | 为终局航程提供核心推进材料 |

正常战役不必强迫玩家按表格全部清空。裂环星后，星图可根据已修复模块、当前货舱、航线风险和玩家选择显示 2–3 个可达节点；高水平驾驶能直接抵达原定目标，受损则可能提前落到另一颗已设计好的星球。

## 16. “不是固定玩法”的具体实现

星球必须是精心设计的，战役却不应是背答案。建议按下列方式兼顾两者：

| 固定的内容 | 变化的内容 |
| --- | --- |
| 行星身份、环境规则、核心任务、关键地标、专属材料 | 下一站选择、到达顺序、航线事件、抵达时飞船损伤、可选异常点和局部资源布局 |
| 每颗星球的主要叙事与必经机制 | 玩家在该星球是按计划登陆还是应急迫降、是否为深空资源绕行、是否提前离开 |
| 最终可修复的飞船模块与升级收益 | 玩家实际携带的货物、已研究蓝图、设施部署方案和防线强度 |

因此，两个玩家都可能在裂环星修好导航后前往不同星球；同一颗赤炉星也可能因为一个人满载抵达、另一个人推进受损迫降，而呈现不同优先级和资源压力。世界观与任务质量由预设保证，重玩价值由系统交互保证。

## 17. 跨星货舱继承规则

| 类别 | 是否带走 | 规则 |
| --- | --- | --- |
| 已修复飞船模块、研究数据、蓝图、解锁科技 | 始终带走 | 属于飞船／知识，不占货舱空间 |
| 铁、虚空晶体、能量、能量核心、氧气罐、推进剂 | 可带走 | 受飞船货舱容量限制；起航前由玩家选择装载 |
| 环境适应数据 | 带走为研究资料 | 不直接让玩家免疫下一星球；新环境仍要重新适应 |
| 地面建筑 | 不直接带走 | 必须像当前规则一样主动回收，返还的材料才能装船；未回收设施留在该星球 |
| 地表节点、植株、当地缓存 | 不带走 | 属于当地环境或已被消耗的世界内容 |

货舱容量应是星际决策，而不是再复制一次人物 25 kg 负重。首版不建议让货舱重量直接增加飞船操作难度；它只限制“该带多少材料、为下一段航行预留多少空间”，避免深空驾驶变成繁琐的配重模拟。

## 18. 建议的落地顺序：先做一个可验证的远征纵切

不应同时制作六颗星球和完整太空驾驶。确认设计后，按下面顺序做，每一步都先在 HTML5 行为规格中通过测试，再同步到现有 Godot 4.6.2 正式工程：

1. **第一颗星球术语与目标迁移**：基地改为飞船；信号阵列、缓存和坚守改为导航／点火叙事，但不改变已验收规则。
2. **飞船状态与维修面板**：四模块、缺失材料、修复收益、持久存档；让当前玩法第一次真正服务于修船。
3. **星图原型**：裂环星起航后出现 2–3 个预设下一站与航线信息；先不用做完整深空操控。
4. **深空航行纵切**：一条陨石带、一次手动规避、一次漂浮资源采集、一次模块损伤／应急着陆判定。
5. **只制作一颗第二星球**：优先推荐“霜环星”或“赤炉星”，验证预设星球的独特主机制与跨星继承。
6. **扩展行星阵列**：第二颗星球完整验收后，再逐颗增加，而不是在没有可玩纵切前铺地图。

## 19. P-02「霜环星」详细设计：能源与热管理的行星

### 19.1 为什么它适合作为第二颗星球

霜环星不是“把裂环星的极寒区放大”。它的核心压力从“个人氧气和区域适应”切换为**飞船与设施的能源调度**，能证明后续行星确实有不同玩法。

- 裂环星已经完整教学了扫描、采集、区域适应、建设、防守与信号阵列。
- 赤炉星会继续放大高温侵蚀，和裂环星内现有熔岩区较接近；更适合作为第三或第四颗星球。
- 霜环星可以直接利用已经验证的太阳能、研究、储物、炮塔、氧气站与防守系统，但赋予它们新的取舍，不需要一上来创造第二套地面动作玩法。

**设计红线：不增加玩家个人“体温条”。** 玩家个人仍以氧气和生命为主；低温作用于飞船、能源设施和可见度，避免把 UI 变成多条并行生存条的负担。

### 19.2 行星身份与抵达前提

| 项目 | 设计 |
| --- | --- |
| 编号／暂名 | P-02「霜环星」 |
| 天体特征 | 绕低亮度恒星运行的冰封行星；长时间处于暮光与白雾中，偶尔穿过短暂而稳定的光窗 |
| 抵达价值 | 取得超导冰晶与低温冷却剂，修复飞船的散热／能源调节模块 |
| 推荐抵达状态 | 裂环星修好基础导航后可选；若深空推进受损，也可以成为第一批应急迫降目标 |
| 核心张力 | 何时发电、何时耗电、何时冒险进入冰裂缝；不是一直跑图采矿 |

### 19.3 地图结构

| 区域 | 风险 | 主要内容 |
| --- | --- | --- |
| 着陆盆地 | 相对稳定 | 飞船落点、初期氧气保障、货舱整理与第一处低风险资源 |
| 暮光平原 | 光照会周期性变化 | 普通资源与太阳能阵列选址；玩家第一次看见“光窗”倒计时 |
| 冰雾裂谷 | 低能见度、扫描距离受扰 | 超导冰晶与地下资源；需要在风暴间隙深入 |
| 低温热泉 | 敌群会被热源与能量吸引 | 部署热能中继的关键地点；提供稳定但有防守压力的供能 |
| 极夜脊线 | 长时间无光、资源价值最高 | 最终冷却剂与飞船模块校准点；适合终局防线 |

地图仍有安全落点和危险边界，但它不复用裂环星的“四个颜色扇区”布局；区域的价值由光照、热源和风暴窗口决定。

### 19.4 核心系统：光窗、储能与热能中继

| 系统 | 玩家看到的规则 | 决策意义 |
| --- | --- | --- |
| 光窗 | 短暂、可预测的有效日照期；太阳能阵列在此期间高效产能，其他时段明显低效 | 玩家提前安排研究、充能、远行和防线消耗 |
| 储能 | 现有“能量”仍供给研究、信号、设施；霜环星更强调提前存够而非临时生产 | 防止玩家在暴风雪后才发现关键设施断能 |
| 热能中继（新设施） | 只能建在低温热泉附近，持续提供稳定能源，但会提升敌人关注度 | 用一处值得守的前线设施，连接建设、炮塔与护盾 |
| 冰雾风暴 | 暂时缩短可视／扫描有效信息，远距导航不可靠；不强制扣血 | 让玩家选择撤回中继站、按地图记忆前进，或等待天气窗口 |

数值在原型实现前另开平衡表确定；这里先定义关系：**光窗提供高效率，热泉提供稳定性，暴风雪制造时机选择。**

### 19.5 资源、任务与飞船收益

| 物品／目标 | 获得方式 | 用途 |
| --- | --- | --- |
| 超导冰晶 | 冰雾裂谷的地表／地下资源点 | 修复导航和能源调节；后续可升级长航行扫描精度 |
| 低温冷却剂 | 极夜脊线任务点与低温热泉研究 | 修复主推进散热，降低下一次高热／长航行的损伤风险 |
| 热泉数据 | 在热能中继在线时完成采样 | 解锁飞船能源调节方案或高效储能蓝图 |
| 冷凝货舱 | 风暴后随机出现的可选缓存 | 可得到推进剂／蓝图碎片，但可能处在无光或敌袭窗口 |

霜环星的离开条件不是“清空资源”。推荐主线为：

1. 在着陆盆地恢复基础供能；
2. 抓住光窗建立储能，并抵达低温热泉；
3. 守住热能中继，研究热泉数据；
4. 在冰雾裂谷和极夜脊线取得两种关键材料；
5. 修复“散热与能源调节模块”，选择继续前往原定星球或利用新能力走更远路线。

### 19.6 抵达状态让同一颗星球不固定

| 抵达方式 | 起始差异 | 体验结果 |
| --- | --- | --- |
| 按计划抵达 | 货舱完整、可自主选着陆盆地附近的第一处设施位置 | 更适合快速完成主线或挑战高风险缓存 |
| 推进受损迫降 | 推进模块带伤，少量货物成为可回收散落缓存 | 先恢复飞船基本机动，再决定是继续修复还是改线 |
| 能源受损抵达 | 太阳能和护盾初始效率受限 | 更早需要热泉中继，防守压力更高 |

同一个手工设计的霜环星因此会有不同开局，但核心机制和世界观不会失控。

## 20. 原型、HTML 与 Godot 的实现边界

### 20.1 结论：核心游戏继续使用同一个 HTML

新玩法**不应另写成第二个独立 `.html` 游戏**。应继续以 `playable/star-abyss.html` 作为唯一可玩行为规格，在内部增加场景／状态切换：

```text
行星地表（裂环星／霜环星…）
        ↓ 起航
星图选择
        ↓ 进入航段
深空航行／陨石群／资源回收
        ↓ 抵达或迫降
下一颗行星地表
```

原因：同一套存档、货舱、飞船损伤、蓝图、目标和测试记录才能连续流转。若拆成第二个 HTML，会重复 HUD、输入、存档和状态同步，并且很容易让两个原型规则漂移。

### 20.2 允许的例外：隔离测试页不是第二个游戏

深空手动操作如果需要独立调试，可以在开发期增加一个只供测试的 `flight-lab` 页面或测试模式，用来验证转向、碰撞、采集和损伤计算；它不保存正式进度，也不是用户进入战役的入口。验证完成后，规则回收到主 HTML。

### 20.3 为什么先在 HTML 验证再同步 Godot

本项目的正式引擎已经确定为 Godot 4.6.2。航线选择、陨石操控、损伤阈值、迫降后果、货舱继承和霜环星能源循环仍先在 HTML 行为规格中快速验证；验证稳定后同步到 Godot，避免在 3D 场景、资源和交互层重复返工。

正确顺序是：

1. 在当前 HTML 原型中完成“裂环星起航 → 星图 → 一段陨石航行 → 霜环星抵达”的最小纵切；
2. 按当前协作方式逐项人工测试、修复并写入验证文档；
3. 该纵切稳定后，把它作为 Godot 3D 的正式行为规格；
4. Godot 只额外验证 3D 专属内容：飞船控制手感、镜头、碰撞体、空间尺度、性能和视觉反馈。

这样不会在 HTML 和 Godot 各测试一遍同一套未定规则；HTML 定规则，Godot 做 3D 正式实现。

---

### 本草案的边界

- 不改变当前 HTML5 原型中已经验收的行为。
- 不把 2D 原型改为 3D；正式 Godot 版本仍按既定交接规则实现 3D 画面与交互。
- 不承诺在讨论前实现上述任何新机制；本文用于先确认主线、命名、节奏和范围。
