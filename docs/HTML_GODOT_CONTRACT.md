# HTML ↔ Godot v3 行为契约

本文记录浏览器规格原型与 Godot 实现应共享的玩家可观察行为。HTML 用于快速验收规则；Godot 保持自己的 3D、场景树和 UI 架构，不逐函数翻译浏览器代码。

## 稳定 ID 与数值

| 领域 | 契约 |
|---|---|
| 资源 | `iron`、`void_crystal`、`biomass`、`energy`、`energy_core`、`blueprint`、`oxygen_canister` |
| 建筑 | `turret`、`o2_station`、`shield_generator`、`solar_panel`、`research_station`、`slow_field`、`signal_beacon` |
| 工具 | `weapon`、`harvester`、`scanner`、`build`、`repair`；数字键 1–5 |
| 区域 | `crash`、`cold`、`heat`、`gravity`；基础氧耗倍率 1.0 / 3.0 / 3.5 / 4.0 |
| 适应 | Lv0–Lv4；效果系数 0 / 0.20 / 0.40 / 0.70 / 1.00；氧耗为 `pressure × (1 - effect × 0.9)`，下限 0.3 |
| 重力区 | Lv0–1 移速 0.7；Lv2+ 恢复 1.0 |
| 熔岩区 | Lv0–1 区内结构每秒损失 0.1 HP；Lv2+ 免疫 |
| 信号 | 每 12 秒原子消费 1 energy，推进 5%；里程碑 `signal_25/50/75/100` |
| 撤离 | `signal_100` 启动 180 秒强制夜晚坚守；不是直接胜利 |
| 存档边界 | 读取 active 且剩余 0 秒的撤离存档时恢复为极短正值，下一逻辑帧结算 |

建筑成本、科技解锁、维修、回收、炮塔升级、血清配方和缓存奖励以 `playable/js/config.js` 为浏览器唯一来源；这些值当前与 `build_manager.gd`、`tech_manager.gd`、`serum_recipes.gd` 和 `signal_log_manager.gd` 对齐。

## 状态与奖励语义

- 顶层状态为 `title / playing / paused / victory / defeat`。
- 面板打开时暂停，关闭后只恢复由该面板触发的暂停；失焦清空 held/pressed 输入。
- 左键只执行当前工具。建造、维修、扫描、采集不会同时开火。
- 资源消费必须先完整检查，失败时不部分扣除。
- 只有玩家或炮塔的合法战斗伤害击杀发放击杀奖励；撞击玩家、基地或结构不发奖励。
- Day 1 首次死亡免掉落；之后约半数资源进入单一可恢复包，重复死亡与已有包合并。
- 复活后恢复可行动氧气并获得短暂无敌，不能形成缺氧无限死亡。
- 里程碑日志、缓存生成和缓存领取均幂等。100% 缓存在坚守期间和胜利后仍可领取。
- 护盾先于基地 HP 吸收；基地 HP 为 0 进入 `defeat`；撤离倒计时归零只进入一次 `victory`。

## 验收场景

1. **输入互斥**：选择 Build 后左键只放置，不生成玩家子弹；Scanner/Harvester/Repair 同理。
2. **死亡恢复**：Day 2 带资源缺氧死亡，出现一个掉落包；3 秒后在基地复活，O2 为 90，能继续移动。
3. **非击杀无奖励**：敌人撞基地消失，库存和击杀数不增加。
4. **七建筑**：资源充足且科技解锁后可分别放置；护盾/太阳能/研究/减速/信号行为可观察。
5. **信号边界**：11.9 秒不扣能量；累计到 12 秒扣 1 并加 5%；断能暂停；读档首帧不额外扣除。
6. **里程碑幂等**：跨越 25/50/75/100 各生成一个日志和缓存；重复注册不重复生成。
7. **撤离**：100% 后状态仍为 playing，显示 180 秒坚守；基地毁灭失败，时间归零胜利。
8. **坏存档**：schema 不匹配或数据不可解析时拒绝继续，并允许新游戏。
9. **响应式 HUD**：1024×768、1366×768、1920×1080 下工具栏、目标、氧气与库存保持可见且可操作。

## 当前验证状态

Node 内置逻辑测试覆盖重量/区域、原子消费、死亡恢复、奖励资格、扫描优先级、建筑操作、信号与里程碑、血清和存档边界。Playwright E2E 已编写；是否执行以当前环境是否安装 Playwright 和浏览器为准，结果记录在最终工作报告和 `docs/REVIEW.md`。
