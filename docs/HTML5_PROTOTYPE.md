# Star Abyss HTML5 可玩规格原型

`playable/star-abyss.html` 是当前 v3 玩法的浏览器行为规格。它是纯 HTML/CSS/经典 JavaScript，运行不需要安装依赖、网络、CDN 或本地服务器；可直接双击并通过 `file://` 游玩。

## 启动与存档

1. 双击 `playable/star-abyss.html`。
2. 选择“新游戏”；标题页的“继续”读取浏览器 `localStorage` 单槽存档。
3. 游戏会在昼夜切换、信号里程碑和页面隐藏时自动保存，也可点击“保存”或按 `P`。
4. “新游戏”与“删除存档”会明确确认覆盖或删除。

不同浏览器和不同文件路径可能使用不同的本地存储隔离区，存档不会跨浏览器同步。

## 操作

| 输入 | 行为 |
|---|---|
| WASD / 方向键 | 移动 |
| Shift | 冲刺（额外耗氧） |
| 1–5 | 武器 / 采集器 / 扫描器 / 建造 / 维修 |
| 左键 | 执行当前工具的主操作；建造工具会先提交位置，再由确认窗口落地或取消 |
| G | 循环扫描资源、O2 植株、研究素材和缓存 |
| F | 使用附近 O2 植株 |
| Q | 使用 O2 Kit |
| B / T | 建筑 / 血清面板 |
| 顶栏“说明” | 打开生存手册；集中说明目标、工具、探索、建筑、区域、面板和存档 |
| X / U / Y | 回收附近结构 / 基地核心内升级扫描器、靠近炮塔升级炮塔 / 解锁当前建筑科技 |
| P | 手动保存 |
| Esc / 右键 | 关闭面板或暂停 |

### 扫描导航规则

扫描初始范围为 360m，启动一次后会跨工具持续搜索，虚线圆环也会持续显示；采空当前目标或移动进入新目标范围时会自动续锁，不需要切回扫描器重复点击。范围外资源不会锁定，并会显示范围不足提示。回到基地核心 65m 内按 `U` 可升级扫描器，最多 Lv3，每级增加 180m 范围，成本为 12 铁 / 3 能量 / 1 蓝图。扫描会始终锁定玩家当前所在区域的匹配资源，即使该区域尚未达到建议适应等级；跨区域目标才需要达到目标区域的建议适应等级。候选优先当前区域，其次按距离从近到远；同距离时地下目标优先。不存在当前区或已适应区的匹配资源时，HUD 会提示“移动后自动续扫”。已揭示的地下资源使用菱形图标和“地下”标识；地表资源保持实心圆。

### 游戏内说明书

- 顶栏“说明”打开可翻页的《生存手册》：概览、探索、区域、建筑、防御、操作六页；页脚显示进度并提供上一页/下一页。
- 建筑页复用建筑配置，逐项列出炮塔、氧气站、护盾发生器、太阳能板、研究站、减速场、信号台的用途、成本和解锁条件；区域页列出四区氧耗、建议适应等级与特殊风险。
- `playable/js/guide.js` 是游戏内说明书的唯一内容源。每次新增或修改玩法，必须同步更新对应手册页、建筑用途文本和本文件；真人验收结果记录在 `docs/HTML5_VERIFICATION.md`。

## 完整闭环

- 2400×1800 俯视世界和跟随相机；坠毁、极寒、熔岩、重力四区均为软压力。
- 可见与地下资源、扫描优先级、O2 植株、25 kg 负重软惩罚、每日保守补给；采集、植株、缓存、死亡掉落和建造可操作当前所在区域，跨区操作则要求目标区域达到建议适应等级；范围圈本身不会绕过跨区限制。地图边框之外不属于任何可探索区域：资源不会在边界外生成、显示、扫描或采集，建筑也不能部署；读取旧存档时会清理越界对象。
- 缺氧或受伤死亡后 3 秒复活，恢复 90 秒氧气和 4 秒无敌；Day 1 首次死亡免掉落，之后约半数资源合并到唯一死亡包。
- 七种建筑：炮塔、氧气站、护盾、太阳能板、研究站、减速场、信号台；建筑目录的每张卡同时显示用途、成本与锁定状态，完整的生存手册通过顶栏“说明”打开；可在当前所在区域远程布置，跨区远程部署则要求目标区域达到建议适应等级（且不能贴近基地核心或与建筑重叠），点击位置后须确认才会扣除资源并立即保存；熔岩区在热适应低于 Lv2 时，预览、确认框和建筑本体均显示高温侵蚀状态与耐久损耗；受损建筑显示耐久条，损毁原因会写入可持久查询的无线电日志；含放置校验、维修、50% 回收、炮塔三级升级和蓝图解锁。
- 四区域 Lv1–Lv4 血清配方及适应公式。
- 信号台每 12 秒原子消费 1 能量并推进 5%；25/50/75/100% 解锁日志和缓存。
- 敌人抵达基地或建筑后不会自毁，而是每 0.8 秒持续攻击（基地每次 4 点伤害，建筑每次 10 点伤害）；只有被玩家武器或炮塔实际击杀才会掉落 2 铁 / 1 生物质，并在通知中标明击杀来源。信号台以天线、脉冲波和“信号台 · 当前进度”世界标签区别于其他建筑；HUD 显示其在线/断能状态，每 12 秒消耗 1 能量并推进 5%，并给出“信号台广播”反馈。100% 进入强制夜晚的 180 秒撤离坚守，不会直接胜利；基地归零失败，倒计时归零胜利，可完整重开。自动存档随确认建造、换日、页面隐藏和刷新更新；顶栏“存档管理”提供自动档与三个独立手动档位，每个显示保存时间、天数和建筑数量后再决定读取。手动档位可分别改名，名称独立保存，覆盖存档与读取后仍保留；留空可恢复默认名称。手动档位必须主动按“保存当前进度”写入，不会自动复制自动档。读档会兼容并修复旧档中的空闲炮塔负冷却计时，不得因此过滤健康建筑。

平衡以正常游玩 30–45 分钟为目标，但尚未完成真人长局统计验证。

## 架构

- `css/game.css`：响应式 HUD、面板、焦点和 reduced-motion。
- `js/config.js`：所有稳定 ID、成本和数值的唯一来源。
- `js/guide.js`：可翻页生存手册的内容源；复用建筑与区域配置生成说明。
- `state/rules/world/buildings/combat/progression/save`：纯状态与领域规则。
- `input.js`：互斥 action 输入、pressed/held 和失焦清理。
- `renderer.js`：只绘制世界；信息密集 HUD 使用 DOM。
- `main.js`：固定 1/60 秒模拟、状态切换和装配。

所有浏览器代码只暴露 `window.StarAbyss` 命名空间。自动化另有不显示在 UI 中的 `window.__STAR_ABYSS_TEST__`，提供 `startNewGame`、`snapshot`、`advance`、`setState`、`save` 和 `load`。

## 测试

```bash
npm test
npm install
npm run test:e2e
```

`npm test` 只使用 Node 内置测试运行器。Playwright 仅是开发期 E2E 依赖，不影响普通运行。

## 已知限制

- 世界和敌人使用直接移动及圆形距离判断，没有障碍寻路。
- 无音频、触屏控制和跨设备存档。
- 程序化图形用于验证规则，不代表最终美术。
- Playwright 浏览器矩阵与完整 30–45 分钟真人通关需在安装开发依赖后继续执行。
