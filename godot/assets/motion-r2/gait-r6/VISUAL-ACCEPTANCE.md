# C2 图像到 3D 的视觉验收缺口

2026-09-29。触发：另一聊天转述用户认为“3D走路跑步太烂，图片很多，实际3D与图片差太多”。该转述按质量反馈记录；本会话此前已有用户明确批准制作 3D，本次只做审核与文档，不新增图片、不重做生产资产。

## 当前结论

R6 的资产保全、导入、物理时钟及所列采样检查仍是有效工程证据；它们不能证明自然度或参考图还原度。**当前视觉质量未获用户认可，不能以工程通过作为完成艺术验收的结论。** 既有 GLB / Blender / 游戏驱动保留，未因本次审核更换 C2。

本次重新直接查看 01-walk、03-jog、04-acceleration 三张原参考，以及 final/ 的 walk/jog/sprint 侧面八相位实帧图。没有新增生成，也没有声称完整观看每份视频。

## 从已看图像能确认的差距

1. 实际 jog 与 sprint 的八相位剪影接近，动作性格的区别不够鲜明；04 图可取的前倾、后蹬、后收腿意图比实帧更强。此为视觉比较，不把前倾角达到某个数值当作自然度通过。
2. 步行实帧有换腿与过腿，但“髋带动大腿—膝自然屈伸—脚跟/前掌转换”的关系，没有通过参考、真实骨架和实际蒙皮同屏证实。早先只显示几组相位拼图，不能让用户直接核对这种关系。
3. 图片角色占画面比例和游戏拼图不同。现有 side 镜头虽是正交相机，位于 (4.5,1.40,0)，看向 (0,0.94,0)，含约 5.8° 俯角；未与参考锁定镜头、尺度和地面线，不能称为严格同视角比较。
4. 原参考自身存在缺陷：01 步行下排与左右标注有重复/错位，底部 HEEL 图错误；03 慢跑多格近似重复且不能建立完整换腿序列；04 主图有可用后收/后蹬，底部支撑腿序列不可靠。必须先注明取用的姿势意图和拒绝的错误，不能按图上编号直接套动作相位。
5. 稳定鞋底材料点的水平滑移尚未测；脚尖朝向、离地和鞋底采样结果不能代替“不滑步”的证据。

## 下一次必须交付的对应关系

每一个对照行固定为：**选中的既有参考格 → 当前 C2 真实骨架关键姿势 → 同一帧游戏蒙皮实帧**。三列采用同侧、同一支撑腿、相同运动事件；以原 C2 身高归一显示，地面线重合。镜头、帧号、相位、实际速度放在画面外的说明区。若参考视角无法精确还原，明确写“近似视角”，不得标作严格对齐。

相位零点按实际左脚接触事件确定，不盲信图上的 0% 或编号。步行至少含左接触、承重、经过支撑脚、前掌推离以及右侧镜像事件；跑步至少含左落地缓冲、支撑后蹬、后侧收腿、腾空换腿以及右侧对应事件。先建立这些事件与真实源帧/游戏帧的一一映射，再谈风格细化。

| 检查项目 | 必须给用户看到的证据 | 不能用来替代的指标 |
| --- | --- | --- |
| 髋与大腿前后摆 | 同一事件的骨盆、髋、膝连线；大腿从髋前经过髋下到髋后 | 只有脚踝往返、单个最大角 |
| 膝屈伸与小腿后收 | 承重缓冲、后侧屈膝收跟、前摆再展开三阶段实帧 | 前踢小腿、抬脚但髋不摆 |
| 脚尖与双脚轨迹 | 同相位正/背视图；双脚各自轨迹与膝方向 | 只看侧面或只读踝骨轴 |
| 跟趾滚动与离地高度 | 同一鞋底材料点、真实接触顺序、平地标尺；记录完整支撑区间 | 仅脚踝锚不动、少数帧没有穿地 |
| 骨盆重心 | 同镜头连续周期的骨盆轨迹，与支撑/腾空事件同时显示 | 单张姿势看似稳定 |
| 手臂对侧摆动 | 肩、肘、腕与同侧髋膝同时叠加；展示左右交换 | 一帧摆臂姿势或负相关数字 |
| 速度、步幅和滑步 | 真正前进的地面标记、根位移、落脚间距和固定材料点世界轨迹 | 原地循环调快、仅 horizontal_speed 字段 |
| 整体自然度 | 正常速度完整循环、起停与换速的短实录，和选定参考并列 | 导出成功、骨数/采样率/数值全绿 |

## 下一轮最小验收顺序

1. 先给步行与跑步各至少三个完整循环的短实录，1 倍实际时间，真实前进、固定地面参照，不用剪辑遮住坏相位。先看侧面，再看正背面。
2. 从这同一段实录抽取关键帧，与选中原参考及真实骨架并列；展示准确帧号和接触事件。画面放大到足以看清膝、脚跟、脚尖，不能缩成只看剪影的小人。
3. 先根据用户看到的短循环修正动作；再检查加速跑是否有清晰前倾、后蹬与步幅变化。不得用更多概念图代替 3D 的修改。
4. 将自然度反馈与工程回归分开记录。只有用户认可实录的视觉效果后，才把“视觉验收”改为通过；仍需保留真实采样范围和未测边界。

复核步骤：打开下面原图与真实侧面图；先检查支撑腿/运动事件是否一致，再核对上表；最后在游戏中 Ctrl+W、W、Shift+W 各走三个周期并松键。若未完成同视角同事件映射，记录为证据缺口，不强行判图与帧一致。
