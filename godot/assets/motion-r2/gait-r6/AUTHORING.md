# C2 步态 R6：可编辑 3D 动作与保全记录

2026-09-29，用户在本聊天明确同意按已展示的 R6 图片方向开发走路、跑步和对应 3D。本轮使用本地 Blender 5.2.1，未再生成图片，未调用付费 3D 服务。此文记录作者侧结果；游戏运行、过渡、地面处理和最终视觉结论由同目录的集成记录及独立审核记录补充。

## 图片到动作的对应

- 采用 `gait-review-r6/04-acceleration.png` 主图 03/07 的髋后伸与前掌蹬离、01/05 和 04/08 的后侧收小腿轮廓。
- 正背对齐图仅指导双轨、膝髋踝朝前的目标。图片审核中已指出的重复腿、错误左右相位、固定摆臂、近水平高抬膝和错误脚跟接触均未照搬。
- 在真实 C2 原比例和原蒙皮上重新编排完整左右周期：左/右半周期错开 0.5；步行先脚跟接近地面、加载、支撑通过、踮脚释放、低位过腿；跑步短支撑后后收小腿，前摆展开再落地。躯干和双臂完成相应反向摆动。

## 文件与时间契约

| 动作 | Blender / GLB 长度 | 整周期前进距离 | 玩法速度 | 支撑占整周期 | 作者采样 |
| --- | ---: | ---: | ---: | ---: | ---: |
| walk | 52/60 秒 | 1.4 m | 1.6 m/s | 0.60 | 105 键 / 120 Hz |
| jog | 35/60 秒 | 4.0 m | 6.8 m/s | 0.22 | 71 键 / 120 Hz |
| sprint | 28/60 秒 | 4.6 m | 10.0 m/s | 0.20 | 57 键 / 120 Hz |

原地动画使用 Y 向上、-Z 为前方。游戏使用移动距离除以 stride 得到相位，再按实际动画长度取样，因此整数时间轴长度与 stride/speed 的小差异不会改动玩法速度。没有改动角色控制器速度。

源文件为 `../source/c2-motion-r2.blend`，完整保留 51 骨、29 个 Actions；新的三个片段有半帧间隔的真实骨骼位置/旋转/缩放关键帧。`../gait_r6.py` 是可修改的姿态设计，`../build_gait_r6.py` 是确定性烘焙和导出入口。IK 和完整鞋底迭代只在离线作者阶段使用。

## 鞋底和朝向

采用全部原始靴子下部顶点的真实变形结果，包含膝与踝混合权重；不再只采踝权重超过 70% 的点，也不把脚跟/尖的 X 坐标假设为零。每个作者采样中校准完整鞋底最低点、实际鞋前后轮廓朝向和左右双轨。作者目标地面为 2 mm，最终可达目标不发生腿长截断。

`foot-definition.json` 保留鞋底定义与初始朝向修正，`contact-material-points.json` 提供真实固定鞋跟/前掌材料点的 rest 位置及所有原始骨权重。前掌材料点用于接触，不等同于视觉鞋尖，不宜用这对最低点代替整鞋轮廓长轴。

最终源文件以 240 Hz（每四分之一原始帧）重新加载测量，结果见 `dense-source-check.json`：

| 检查 | walk | jog | sprint |
| --- | ---: | ---: | ---: |
| 最低实际鞋底 | +1.876 mm | +0.994 mm | +0.225 mm |
| 大腿前后角范围 | -20.85° 至 +33.58° | -24.26° 至 +52.01° | -24.77° 至 +53.53° |
| 膝屈曲范围 | 14.39° 至 44.26° | 27.44° 至 107.02° | 32.49° 至 115.84° |
| 最高膝盖相对髋高度 | -342.6 mm | -253.1 mm | -244.4 mm |
| 51 骨首尾矩阵误差 | 0 | 0 | 0 |

骨段长度在全部密集采样中保持原值，数值误差小于 0.003 mm。作者关键帧真实鞋长轴误差不超过 0.15°。这些是源动作数据，不能代替游戏最终 GPU 蒙皮与混合过渡的检查。

## 原资产保全

修改生产前完整备份到 `../source/gait-r6-before/`，含原 `.blend`、GLB、clips、旧构建脚本和 runtime，`snapshot.json` 记录字节长度及 SHA-256。备份已存在时禁止覆盖；重建总从这份备份开始。

为保留无关动作的原导出字节，新动作以保留半帧关键帧的方式导出，`merge_gait_glb.py` 仅把 walk/jog/sprint 的 animation payload 合入原 GLB。`verify_export.py` 已证明：

- 29 个动作中仅 walk、jog、sprint 变化，其他 26 个动作逐通道、输入输出访问器完全相同。
- 五个网格的顶点属性、原权重、三角索引、材质分配完全相同。
- 51 骨 inverse bind、材质 JSON 和四张内嵌 PNG 字节完全相同。
- 当前验过的 GLB SHA-256：`9e65aa43ef2a925de92771cdba9680039ce24e842e1327cd34718a95f6d1da05`。

未通过的第一份可视候选保留为 `candidate.glb`，其 SHA 为 `1aca36aaf92094bee3b2a1f596b0cfdb51a6c2d2c3280c3425737fbf7c13e5b2`。它不是生产结果，不要误把该旧候选接回游戏。

## 可复现验证

在工作树根目录运行：

```bat
D:\blender\blender.exe -b -t 2 --python godot/assets/motion-r2/build_gait_r6.py
D:\blender\blender.exe -b -t 2 --python godot/assets/motion-r2/gait-r6/verify_source_dense.py
D:\blender\5.2\python\bin\python.exe godot/assets/motion-r2/gait-r6/verify_export.py
```

游戏核对：按正常玩法速度分别走、跑、冲刺；侧面看大腿前后摆、支撑腿通过、后收与摆臂；正背看靴尖正前、膝盖不外甩且双轨不交叉；再检查启动、停止、转向和步行/跑步切换中的真实蒙皮鞋底。源动作检查不能证明 runtime 混合和脚锁处理正确，最终集成必须另验。
